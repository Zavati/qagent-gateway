# 08.1.8-FIX-1 — Origens da autonomia derivadas do Environment

## Resultado
A tela de autonomia não exige digitar origens. O Gateway deriva um resumo seguro das URLs cadastradas no mesmo tenant/projeto/ambiente. A delegação continua explícita e fixa `allowedOrigins` na política existente do Orchestrator. Abrir, atualizar e salvar a política não inicia ciclo, Run, análise ou chamada de IA.

## Fontes e escopo
- `environment.webBaseUrl`, quando cadastrada.
- API Base URLs dos bindings ativos do ambiente com serviços ativos.
- Autenticação dinâmica `api_service`: sua origem é a API Base URL do serviço referenciado nesse mesmo ambiente. Binding ausente é diagnosticado, nunca substituído pelo host web.
- Autenticação `runtime_origin`: não cria host; usa a origem materializada da request, conferida pelo guard existente. Basic/api_key/none não acrescentam destino de troca HTTP.
- Não usa observações, URL do navegador ou configuração de outro ambiente para ampliar a lista. Não consulta valores de variáveis nem descriptografa secrets. O leitor público existente de auth consulta metadados de credencial, sem retornar ciphertext/valores no DTO.

A normalização extrai apenas `URL.origin` (protocolo, host e porta). Os paths das URLs cadastradas permanecem intactos e continuam pertencendo à execução. Repetições são consolidadas, fontes identificadas e lista ordenada. Sem URLs, configuração inválida/ambígua, auth sem mapping ou mais de dez origens produz diagnóstico; não há truncamento silencioso. Ambiente só com API Base URLs não precisa de Web Base URL redundante.

## Contrato público aditivo
GET `.../autonomous-learning/policy?environmentId=...` conserva política/permissões e acrescenta `environmentOrigins`, contrato `qagent.autonomous-environment-origins.v1`: escopo, nome do ambiente, `status`, `allowedOrigins`, `entries[{origin,sources}]`, `originsHash`, `runtimeOriginAuthProfileCount` e `issues` sem URL inválida, path, payload, token ou mensagem upstream.

O novo Console envia os campos de consentimento/limites anteriores, mas em vez de `allowedOrigins` envia:
```json
{ "originSelection": { "source": "ENVIRONMENT_CONFIG", "originsHash": "<hash hexadecimal recebido na leitura>" } }
```
Este é um trecho ilustrativo, não o body completo. O Gateway recalcula as origens na gravação, exige igualdade do hash e só então preenche `allowedOrigins` no contrato interno anterior. `originSelection` e `allowedOrigins` juntos são recusados. O hash inclui organização, projeto, ambiente e conjunto canônico de origens; não é uma assinatura nem substitui autorização. Labels, ordem ou paths mudados no mesmo host não ampliam a delegação nem invalidam esse hash.

O contrato armazenado, HMAC/tickets, fila, budgets e callbacks permanecem iguais. A API antiga de owner/admin que recebe `allowedOrigins` explícito continua compatível; não é usada pela UI nova. Não foi criado endpoint de execução nem bypass do controle de destinos.

## Consistência e alteração da configuração
O resumo atual e a lista da política salva são separados. Um novo host não entra em políticas/ciclos existentes por leitura. A UI mostra origens adicionadas/removidas; atualizar exige confirmar e salvar nova revisão. Enquanto houver diferença, o novo Console não inicia outro ciclo dessa política. APIs/ciclos anteriores continuam presos à lista já autorizada; alterar configuração, por si só, não revoga destinos antigos. Para retirar autorização imediatamente, usar revogação/pausa existente.

Se os destinos mudarem entre preview e PUT, o Gateway retorna `AUTONOMOUS_ENVIRONMENT_ORIGINS_CHANGED` sem enviar a gravação ao Orchestrator. A UI limpa consentimentos, permite atualizar e confirmar novamente. Não há transação global entre o banco de configuração e o banco de política: uma mudança posterior não amplia a lista fixada, e o runtime continua validando o destino real contra ela.

Revogar continua possível com URLs incompletas ou metadata temporariamente indisponível, desde que projeto/ambiente e política ainda possam ser consultados. Metadados ausentes de Gateway antigo desabilitam a nova gravação, sem fallback para um input manual. Respostas atrasadas de outro ambiente/sessão são descartadas. A atualização com o mesmo hash/revisão não força repetir um consentimento ainda não enviado.

## UI
Resumo **Destinos do ambiente STG**, somente leitura, tags Web Base URL/API Services/Autenticação. Não há textarea de origens. Configuração faltante oferece **Configurar ambiente no projeto** (`/projects/configuration?projectId=...`); essa rota existente não fixa o ambiente por query, portanto selecione o ambiente correto nessa página.
